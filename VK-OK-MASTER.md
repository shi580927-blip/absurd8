# MASTER — Кот Шеф: VK Mini Apps + Одноклассники

## 1. Назначение

Этот документ — источник истины для платформенной версии игры **«Кот, который слишком хорошо живёт»** для **VK Mini Apps и Одноклассников**.

Базовая Яндекс-версия живёт в ветке `main` и не изменяется работами по VK/ОК.

Рабочая ветка платформенной версии:

`platform/vk-ok`

Точка ответвления от стабильного Яндекс-релиза:

`9a8c275f9c590cedb12630dad5a4c392113bd77d`

Главный принцип: **одна игровая логика, отдельный платформенный слой**. Перенос на VK/ОК не должен менять механику, баланс, уровни, блюда, помощников, визуал, расположение интерфейса или ассеты без отдельной задачи.

---

## 2. Что остаётся общим

Без изменений сохраняются:

- игровая сцена 16:9;
- landscape на компьютере и мобильных устройствах;
- заглушка поворота телефона в portrait;
- игровые механики;
- уровни и баланс;
- блюда, помощники, таймеры, события;
- UI и CSS;
- ассеты;
- Web Audio;
- локальное резервное сохранение;
- test mode `?test=1`;
- обработка `visibilitychange`, `blur`, `focus`;
- офлайн-доход и обычный игровой цикл.

---

## 3. Что заменено только для VK/ОК

В ветке `platform/vk-ok` Яндекс-платформенный слой заменён на общий адаптер `platform-vk-ok.js`.

Не используются:

- `/sdk.js`;
- `YaGames.init()`;
- `ysdk`;
- Player API Яндекс Игр;
- `LoadingAPI.ready()`;
- `GameplayAPI.start()/stop()`;
- `ysdk.adv.showRewardedVideo()`;
- определение языка через `ysdk.environment.i18n.lang`.

Используются:

- VK Bridge;
- `VKWebAppInit`;
- `VKWebAppStorageGet` / `VKWebAppStorageSet`;
- `VKWebAppShowNativeAds` с rewarded для VK;
- OK FAPI `loadAd()/showLoadedAd()` для rewarded в Одноклассниках;
- `VKWebAppViewHide` / `VKWebAppViewRestore` там, где поддерживаются;
- резервные browser lifecycle-события;
- русский язык в текущей VK/ОК-версии.

Для Одноклассников клиент определяется через параметр `vk_client=ok`.

---

## 4. Сохранения

Главное сохранение остаётся единым объектом состояния игры.

Порядок:

1. локальный `localStorage` остаётся резервной копией;
2. платформенное сохранение выполняется через VK Storage;
3. большие данные разбиваются на несколько storage-ключей;
4. при старте более свежее корректное облачное состояние может заменить локальное;
5. test mode не должен загрязнять облачный прогресс.

Любое изменение структуры сохранения требует отдельной проверки:
- новый игрок;
- старое локальное сохранение;
- облачное сохранение;
- перезагрузка;
- вход с другого устройства;
- отсутствие/ошибка Bridge.

---

## 5. Rewarded-реклама

Реклама только добровольная rewarded.

Бизнес-логика награды остаётся в `game.js`; платформенный слой только показывает рекламу и возвращает результат.

Награда выдаётся **только после подтверждённого успешного просмотра**.

VK:
- `VKWebAppShowNativeAds`;
- формат `reward`.

ОК:
- `FAPI.UI.loadAd()`;
- после подготовки выдерживается необходимый интервал;
- затем `FAPI.UI.showLoadedAd()`;
- награда только после успешного завершения показа.

При ошибке, закрытии или недоступной рекламе награда не выдаётся.

Существующий cooldown рекламы и игровые ограничения сохраняются.

---

## 6. Lifecycle и звук

При рекламе, сворачивании, уходе приложения в background:

- геймплей ставится на паузу;
- музыка и звуки останавливаются;
- временные события не продолжают работать как активная сцена.

После возврата:

- игра корректно возобновляется;
- звук не запускается повторно поверх уже играющего;
- таймеры не получают двойное начисление.

Используются и платформенные события, и browser fallback.

---

## 7. Тестовый режим

`?test=1` остаётся доступен только для разработки.

В VK/ОК-ветке в тестовой панели дополнительно показывается статус:

- platform;
- client = VK или OK;
- Bridge;
- cloud save;
- OK FAPI;
- состояние подготовки рекламы.

Обычный игрок эту диагностику не видит.

---

## 8. Хостинг, сборка и публикация

Основной хостинг VK/ОК-версии — **SprintHost**, на поддомене сайта `kingdom1.ru`.

Архитектура доменов:

- отдельный поддомен под сайт/страницу студии Mintyberries Games;
- отдельный поддомен под VK/ОК-версию «Кота Шефа»;
- Яндекс-версия и её GitHub Pages не используются как хостинг VK/ОК-версии.

Рекомендуемая схема имён:

- `games.kingdom1.ru` — студия Mintyberries Games;
- `cat-vk.kingdom1.ru` — отдельная размещённая сборка «Кота Шефа» для VK Mini Apps и Одноклассников.

Финальные имена поддоменов могут быть изменены без изменения архитектуры.

Основной рабочий поток:

**ветка `platform/vk-ok` → автоматическая проверка → ZIP-артефакт → загрузка файлов на отдельный поддомен SprintHost → проверка HTTPS → этот URL указывается в VK Mini Apps → та же платформенная версия используется для Одноклассников.**

ZIP сохраняется как воспроизводимая релизная сборка и резерв, даже если запуск идёт с SprintHost.

Сборка выполняется GitHub Actions:

`.github/workflows/package-vk-ok.yml`

Артефакт:

`kot-shef-vk-ok`

В релизной папке/ZIP:
- `index.html` в корне;
- игровые HTML/JS/CSS;
- `platform-vk-ok.js`;
- необходимые ассеты;
- без документов разработки;
- без submission-assets;
- без scripts;
- без Яндекс SDK и Яндекс API.

На SprintHost содержимое релизной сборки выкладывается **в корень каталога игрового поддомена**, чтобы `index.html` открывался по корневому URL без дополнительных путей.

## 9. Что нельзя делать

Без отдельного задания нельзя:

- изменять `main` ради VK/ОК;
- сливать `platform/vk-ok` в `main`;
- удалять Яндекс-чек-листы и документы;
- заменять игровые ассеты;
- менять баланс;
- менять механику;
- менять расположение UI;
- удалять EN-ресурсы только потому, что текущая VK/ОК-версия русская;
- добавлять платный хостинг;
- переносить игру на другую архитектуру;
- подключать покупки до отдельного этапа.

---

## 10. Порядок работы разработчика

1. Все изменения VK/ОК — только в `platform/vk-ok`.
2. Перед изменениями проверять, что `main` не затронут.
3. Менять только платформенный слой или явно поставленную задачу.
4. После изменения запускать синтаксическую и автоматическую проверку.
5. Проверять GitHub Actions `Package VK OK`.
6. Собирать ZIP.
7. Размещать релизную сборку на отдельном поддомене SprintHost.
8. Проверять HTTPS и прямое открытие `index.html`.
9. Тестировать VK: desktop + mobile.
10. Тестировать ОК: desktop + mobile.
11. Проверять сохранение, повторный вход, rewarded, pause/resume и звук.
12. Только после этого считать релиз готовым.
